# PINTE Guides 双语内容工厂设计

## 1. 目标

在现有网站 `/guides/` 体系下建立可持续扩展的双语技术内容库：

- 建立 10,000 个独立烫金行业选题。
- 每个选题分别撰写英文版和中文版，共 20,000 个可索引页面。
- 每批发布 50-100 个选题，即 100-200 个本地化 URL。
- 所有页面面向包装厂、印刷厂、礼盒厂、标签厂、化妆品包材厂、塑料件加工厂和皮具厂客户。
- 客户可见正文、标题、meta 和结构化数据不得出现 SEO、GEO、AI search optimization 等内部策略词。
- 内容必须连接到具体底材、工艺、故障、测试、产品和打样动作，而不是只扩展关键词数量。

## 2. 非目标

- 不将新批量内容写入 Notion Blog。
- 不一次性发布全部 20,000 个页面。
- 不按照关键词排列组合生成近似页面。
- 不虚构测试结果、认证、客户案例、价格、参数或产品能力。
- 不购买垃圾外链，不伪造论坛或 Reddit 推荐。
- 不要求每篇文章达到完全相同的长度。

## 3. 内容架构

### 3.1 十二个主题集群

1. 烫金基础与术语
2. 烫金膜结构与涂层
3. 纸张与覆膜底材
4. 塑料、玻璃与金属底材
5. 皮革、布料与书封
6. 包装与行业应用
7. 热烫、冷烫与数码烫对比
8. 设备、烫版与生产参数
9. 附着、掉金、糊版等故障
10. 测试、质量和合规
11. 采购、规格、MOQ 与供应商
12. 环保、设计趋势与新工艺

每个集群包含以下页面类型：

- 集群核心指南
- 单一问题深度页
- 底材或应用场景页
- 故障排查页
- 工艺和产品对比页
- 测试方法与采购清单页
- 经确认的真实案例页

### 3.2 URL 结构

中英文使用同一个稳定英文 slug，通过语言前缀区分：

```text
/en/guides/hot-foil-adhesion-on-uv-inkjet-labels/
/cn/guides/hot-foil-adhesion-on-uv-inkjet-labels/
```

每个语言版本必须具备：

- 自引用 canonical
- 指向另一语言版本的 hreflang
- `x-default` 指向英文版本
- 稳定且不可随标题调整而随意变化的 slug

### 3.3 内容文件

新文章不继续堆叠在 `data/geoGuides.ts` 单一文件中。采用配对目录：

```text
content/guides/
  <topic-id>/
    en.md
    cn.md
```

选题清单单独维护，记录集群、搜索意图、状态、主问题、相关产品和来源：

```text
content/guides/topics.json
```

文章状态为：

```text
draft -> reviewed -> published
```

只有 `published` 状态可进入路由、导航、预渲染和 sitemap。

## 4. 文章数据模型

每个 Markdown 文件必须包含 YAML frontmatter：

```yaml
topic_id: HF-000001
lang: en
slug: hot-foil-adhesion-on-uv-inkjet-labels
status: draft
cluster: troubleshooting
intent: troubleshooting
title: Why Hot Foil Does Not Adhere to UV Inkjet Labels
description: A practical diagnostic guide for incomplete transfer and weak adhesion.
primary_keyword: hot foil adhesion on UV inkjet labels
secondary_keywords: []
related_products: []
related_guides: []
sources: []
author: PINTE Technical Team
reviewer: PINTE Application Engineer
date_published:
date_modified: 2026-07-16
hero_image:
hero_alt:
```

中英文文件必须使用相同 `topic_id` 和 `slug`。事实底稿一致，但正文分别按目标市场语言撰写，不做机械翻译。

## 5. 内容质量标准

### 5.1 内容长度

- 中文通常为 1,500-3,500 字。
- 英文通常为 1,200-2,500 words。
- 故障、测试和综合采购指南可以更长。
- 简单术语不强行扩写，必要时并入更完整的核心页面。

### 5.2 标准文章结构

1. 开头 40-100 字直接回答问题。
2. 说明适用底材、应用和不适用条件。
3. 解释温度、压力、速度、停留时间、版材、油墨或表面处理等关键变量。
4. 提供“现象 - 可能原因 - 验证方法 - 下一步动作”表格。
5. 给出打样流程和通过/失败判定方法。
6. 对应 PINTE 产品系列，但不做未经验证的绝对承诺。
7. 提供样品申请或询盘入口。
8. 添加可见 FAQ 和与其一致的结构化数据。
9. 添加来源列表、作者、技术审核人和更新时间。

推荐参数必须明确说明其用途是测试起点，最终参数需根据实际底材、机器、图案和生产速度打样确认。

### 5.3 来源优先级

1. PINTE 自有产品资料、测试记录、案例和 HotFoil_Database。
2. 标准机构、行业协会和法规主管机构。
3. 设备厂商、材料厂商和具备技术资料的行业企业。
4. 可信行业媒体和技术出版物。
5. Reddit、论坛和问答网站只用于发现问题及用户语言，不作为关键参数的唯一证据。

每篇文章通常添加：

- 4-8 个站内上下文链接。
- 2-5 个支持正文事实的外部来源链接。

外部引用链接是来源说明，不等同于指向 PINTE 的 backlink。

### 5.4 禁止发布条件

出现以下任一情况时不得将状态改为 `published`：

- 中英文文件缺失或 topic_id 不匹配。
- 标题、主问题或正文与现有页面高度重复。
- 包含无来源的具体认证、测试次数、容差或性能承诺。
- 包含占位符、空章节、失效来源或无法解释的自动生成段落。
- 客户可见内容包含内部策略词。
- 没有相关产品、相关指南或样品申请入口。
- canonical、hreflang 或 slug 不一致。

## 6. 关键词与选题管理

10,000 个选题先形成选题库存，不直接形成公开页面。每个选题必须记录：

- 主问题和核心搜索意图
- 主题集群
- 采购阶段
- 底材、行业、工艺和故障标签
- 相关产品系列
- 计划引用来源
- 与现有页面的差异说明
- 中英文发布状态

选题去重以搜索意图为主，而不是只比较字面关键词。同一问题的单复数、不同语序、同义词和地区表达应合并到一个主页面中。

## 7. 页面呈现

`/guides/` 首页仅展示主题集群、重点指南、筛选和搜索，不直接平铺全部文章。

文章页必须提供：

- 所属集群导航
- 相关底材和工艺
- 相关故障和测试页
- 相关 PINTE 产品
- 上一篇/下一篇或同主题推荐
- 样品申请和询盘入口

页面正文、表格和关键答案必须存在于可抓取 HTML 中，不依赖客户端接口请求后才出现。

## 8. 结构化数据与发现

每个已发布页面生成：

- `Article`
- `BreadcrumbList`
- 与可见 FAQ 一致的 `FAQPage`
- 涉及具体产品时使用真实、可验证的 `Product` 数据
- 有实际图片时使用 `ImageObject`

不得虚构价格、库存、评分或评论来满足富结果字段。

每批发布时：

1. sitemap 持续包含全部 `published` URL，绝不包含 draft 或 reviewed 页面。
2. 为新增或更新页面写入真实 `lastmod`。
3. 为有效文章和产品图片输出 caption。
4. 校验 canonical 和 hreflang。
5. 构建成功后提交 IndexNow。

## 9. 发布流程

### 阶段 A：内容系统

- 建立内容目录和 schema。
- 建立选题库存格式。
- 建立 Markdown 加载、页面渲染和预渲染。
- 建立 sitemap、站内导航和校验脚本。

### 阶段 B：10,000 个选题库存

- 从行业术语、底材、工艺、故障、设备、测试、应用和采购问题扩展选题。
- 合并相同搜索意图。
- 标记 P0/P1/P2 优先级。
- 不在该阶段生成低质量公开页面。

### 阶段 C：首批内容

首批生产 50 个选题、100 个中英文页面，优先覆盖：

- UV 数码标签烫金附着
- PP/PE 掉金和表面能
- 纹理皮革和 PU/PVC 皮革
- 覆膜纸、UV 光油和粗纹纸
- 热烫、冷烫、数码烫、Sleeking 和金墨对比
- 大面积发花、针孔、细线断金和糊边
- 烫金与压凸套准
- 耐酒精、耐磨、胶带和刮擦测试
- 打样参数矩阵
- 供应商和卷料规格确认

### 阶段 D：持续扩展

每批发布 50-100 个选题。发布后观察收录、曝光、引用、站内转化和询盘，再决定下一批优先级。

## 10. 自动校验

发布前校验至少包括：

- frontmatter 必填字段
- topic_id、slug 和语言配对
- 标题、主问题和正文相似度
- 内部策略词扫描
- 外部链接格式和可访问性
- 站内链接目标是否存在
- 相关产品是否存在
- FAQ 可见内容与 JSON-LD 一致
- canonical/hreflang 对称性
- sitemap 只包含 published 页面
- 页面预渲染结果包含正文而不是空壳

校验失败必须阻止该文章进入公开 sitemap，但不阻止其他通过审核的文章发布。

## 11. 监控与暂停规则

每批发布后记录：

- Google 和 Bing 收录率
- 抓取错误与已抓取未索引数量
- canonical 和 hreflang 异常
- 搜索曝光、点击和非品牌查询
- ChatGPT、Google AI 和 Perplexity 的引用样本
- 指南到产品页、样品页和询盘页的转化
- `utm_source=chatgpt.com` 等推荐流量
- 各主题集群产生的有效询盘

如果连续两个批次出现大面积未索引、相似页面或无曝光，应暂停扩量，合并、删除或重写问题页面。

## 12. Backlink 策略

文章中的外部链接用于事实引用，不会自动产生指向 PINTE 的 backlink。真正的 backlink 通过以下资产获取：

- 原创底材兼容矩阵
- 真实故障照片和测试报告
- 可引用的烫金参数实验
- 行业媒体投稿
- 客户或设备合作案例
- 对 Reddit 和行业社区问题的公开、披露身份的技术回答

不使用批量目录垃圾提交、付费垃圾链接、伪造论坛账号或无关站点互链。

## 13. 验收标准

内容系统完成时：

- 可从 Markdown 配对内容生成中英文 guide 页面。
- 只有 published 页面进入导航和 sitemap。
- 页面具有可抓取正文、正确 canonical、hreflang 和结构化数据。
- 校验脚本可以阻止不完整、重复或不合规内容发布。
- 首批 50 个选题通过人工技术审核。
- Cloudflare 构建和预渲染在规定批次规模下稳定完成。

10,000 个选题库存完成不等于 20,000 个页面立即上线。最终目标是在质量门槛和批次监控机制下逐步完成全部双语页面。
