# Guides Topic Inventory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a deterministic, deduplicated inventory of exactly 10,000 bilingual hot-stamping topics without publishing thin or templated pages.

**Architecture:** A curated taxonomy defines valid industries, substrates, processes, defects, tests, equipment, procurement stages, and question intents. A generator applies intent-specific rules, creates draft topic records, deduplicates by normalized intent key, scores priority, and emits coverage and collision reports; no article files are generated by this plan.

**Tech Stack:** Node.js ESM, JSON source data, Node test runner.

## Global Constraints

- Exactly 10,000 topic records; each represents one future bilingual pair and therefore two possible localized URLs.
- Every record starts as `draft`; inventory creation must not add routes or sitemap URLs.
- Similar wording with the same user intent must collapse into one topic.
- The inventory must cover all 12 approved clusters.
- Public proposed titles must not contain internal SEO/GEO/AI strategy terms.
- Topic records may be generated from curated dimensions, but complete article pages may not be generated by Cartesian substitution.

---

## File Structure

- Create `content/guides/taxonomy.json`: curated domain dimensions and valid compatibility groups.
- Create `content/guides/source-registry.json`: reusable official and industry source metadata.
- Create `scripts/lib/guide-topics.mjs`: normalized intent keys, candidate builders, scoring, and deduplication.
- Create `scripts/generate-guide-topics.mjs`: deterministic 10,000-topic CLI.
- Create `scripts/guide-topics.test.mjs`: exact-count, uniqueness, cluster coverage, and forbidden-term tests.
- Create `reports/guides/topic-inventory-summary.json`: generated coverage report.
- Modify `content/guides/topics.json`: replace fixture-only inventory with 10,000 draft records.
- Modify `package.json`: topic generation/test commands.

### Task 2: Topic Generator with Intent-Level Deduplication

**Files:**
- Create: `scripts/lib/guide-topics.mjs`
- Create: `scripts/guide-topics.test.mjs`

**Interfaces:**
- Produces: `normalizeIntentKey(candidate): string`
- Produces: `generateCandidates(taxonomy): TopicCandidate[]`
- Produces: `selectInventory(candidates, count): TopicRecord[]`
- Produces: `summarizeInventory(records): InventorySummary`

- [ ] **Step 1: Write failing generator tests**

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import taxonomy from '../content/guides/taxonomy.json' with { type: 'json' };
import { generateCandidates, selectInventory, summarizeInventory } from './lib/guide-topics.mjs';

test('selects exactly 10000 unique draft topics', () => {
  const inventory = selectInventory(generateCandidates(taxonomy), 10000);
  assert.equal(inventory.length, 10000);
  assert.equal(new Set(inventory.map((item) => item.topic_id)).size, 10000);
  assert.equal(new Set(inventory.map((item) => item.intent_key)).size, 10000);
  assert.ok(inventory.every((item) => item.status === 'draft'));
});

test('covers all twelve clusters without internal strategy words', () => {
  const inventory = selectInventory(generateCandidates(taxonomy), 10000);
  assert.equal(new Set(inventory.map((item) => item.cluster)).size, 12);
  assert.ok(inventory.every((item) => !/\b(?:SEO|GEO|ChatGPT|Perplexity|AI search)\b/i.test(`${item.title.en} ${item.title.cn}`)));
});

test('summary reports no duplicate slug or intent key', () => {
  const summary = summarizeInventory(selectInventory(generateCandidates(taxonomy), 10000));
  assert.equal(summary.duplicateSlugs, 0);
  assert.equal(summary.duplicateIntentKeys, 0);
});
```

- [ ] **Step 2: Run tests and verify failure**

Run `node --test scripts/guide-topics.test.mjs`.

Expected: module-not-found failure.

- [ ] **Step 3: Implement valid candidate families**

Implement separate builders for definition, comparison, substrate selection, troubleshooting, parameter, testing, application, equipment, procurement, compliance, sustainability, and design/prepress intents. - [ ] **Step 4: Implement deterministic scoring and selection**

Score candidates by buyer proximity, technical specificity, source availability, product relevance, and overlap risk. Sort by score, stable intent key, and title; select a balanced quota per cluster before filling remaining positions. IDs must be `HF-000001` through `HF-010000` after final sorting.
